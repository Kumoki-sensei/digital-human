# 里程碑与决策记录

## 坑记录（排障花掉的时间都在这，别再踩）

| 坑 | 表现 | 根因与结论 |
|---|---|---|
| **语音播报默认开着** | 用户一发消息网页就自己开口说话，把人吓一跳 | 会出声的功能默认必须关。`voice.autoplay` 默认 false，且前后端两个开关（autoplay/tts_enabled）要分清 |
| 开关发了后端不认识的字段名 | 勾了「自动播放」却没声音：前端发 `autoplay`，后端只认 `tts_enabled` | 前后端协议字段以 `api/schema.py` 为准，别自造名字 |
| Starlette `MutableHeaders` 没有 `.pop()` | 所有静态资源 500 → 前端整体不加载 | 只能用 `del headers['etag']`；写 `pop` 直接崩 |
| 浏览器缓存前端 JS/CSS | 改完代码刷新看到的还是旧逻辑，排查方向全跑偏 | `backend/main.py` 的 `NoCacheStaticFiles` 强制 no-cache |
| 同一事件被两处渲染 | 每句回复在界面上出现两遍；监听器数量与模块实例数都正常，极难定位 | **一个事件只允许有一个渲染者**（当时 `browserSpeak` 与 `ws:segment` 各渲染一次） |
| `MediaRecorder` 产出的 webm | 部分环境 `decodeAudioData` 解码失败 | `audio.js` 保留 `<audio>` 兜底路径，口型退化用估算能量 |
| AudioContext suspended | 自动化环境里永远无声、能量恒 0 | 浏览器要求用户手势，真人点一次即可；不是代码问题 |
| WebSocket 重连有次数上限 | 后端重启后网页永久失联 | 改无限重试 + 退避封顶 30s，且 visibilitychange/online 立即重试 |
| 「清空记忆」只发 reset 不换 session | 刷新后旧历史又回来了 | 必须换新 session id 并重连 |
| 本机 `python` 命令 | 指向 Store 存根，静默无输出 | 一律 `uv run python` |

## M0 骨架（已完成）

端到端跑通：一条命令启动，网页能对话、能出声、有形象位、能换肤、能接自己的密钥。

- 后端：FastAPI + WebSocket 双向流（文本 / 二进制音频 / 打断信号 / 流式事件）
- 四能力接口统一注册表 + Protocol，OpenAI 兼容协议可插拔
- 用户自带密钥通道（连接参数 `p=cap.field:value`，即用即弃不落盘）
- 工具调用（能做）+ 确认中心（写操作两段式确认）+ 一轮 3 次往返上限
- 会话记忆：滚动窗口 + 原子落盘 JSON，重启可续，可列出/载入历史
- 前端三件套分离：`index.html` / `styles/` / `scripts/`（原生 ES Module，无构建）
- 换肤系统：设计令牌 + 4 套皮肤 + 运行时热切换 + 外挂 JS 皮肤钩子（`raf`/`listen` 自动清理）
- Live2D 装载层：自写 WebGL 直用 Cubism Core；模型缺失时降级为纯 CSS 占位形象
- 口型同步：WebAudio 分析器实时驱动；无分析器时退化为估算能量
- 视觉：截屏/摄像头取帧 → 多模态模型；涉及隐私必须走确认中心
- 开发辅助：`tools/check_env.py` 环境自检、Core/示例模型下载脚本、`scripts/dev.ps1`

### 已知未验证（诚实清单）

1. **Live2D 渲染不出来** —— 模型能加载（134 drawable、125 次 draw call、GL 错误 0），
   但画布无像素输出。已修掉 6 个实质 bug（顶点/索引的分组语义、索引局部编号、
   vertexCounts 单位、归一化坐标矩阵、rAF 被暂停），根因仍未定位。
   当前已做**自动回退**：检测到画布无输出即切回 CSS 占位形象并在页面写明原因，
   不会让用户对着空白画布。排障入口：`canvas.__dhRender`（矩阵/顶点数/UV 范围/GL 错误）。
2. **口型与语音播报未在真人手势下验证** —— 自动化环境里 AudioContext 必然 suspended。
3. **麦克风相关路径未在真人设备上验证** —— 自动断句的算法层有 23 条断言覆盖，
   但 `getUserMedia` / AudioWorklet 的真实采集链路只能在有麦克风的机器上验。
4. **本机 ASR / TTS 未验证** —— 需先装 ffmpeg 与对应 extra 依赖。
5. **`_tmp/` 下有若干残留空目录删不掉**（权限异常，`Access denied`）。
   不影响项目与 git（`_tmp/` 本身被忽略），清理器会处理；若要手动删需管理员权限。

## M1 语音链路硬化（进行中）

- [x] **延迟仪表盘**（已完成）—— 三段埋点：听懂(ASR) / 首字(LLM) / 首帧(TTS)，
      外加每次工具的耗时与每个分句的合成时长；点状态栏的 `xxxxms` 展开分解，
      每轮结束自动亮出。浏览器 TTS 拿不到音频流，首帧值标注为「墙钟估算」不假装精确。
      后端同时打一行 `本轮耗时：听懂 x｜首字 y｜首帧 z｜工具 n 次` 进日志。
- [x] **VAD 自动断句**（已完成）—— 说完自动发送，不用再点麦克风。
      - `web/scripts/vad.js`：算法与浏览器 API 完全解耦（只吃 Float32 PCM + 时间戳），
        所以能离线单测；自适应噪声底 + 三段状态机（静音/说话/完成）+
        最短语音过滤（咳嗽、键盘声）+ 最长时长兜底。
      - `web/scripts/mic-worklet.js`：AudioWorklet 取原始 PCM（MediaRecorder 拿不到采样，
        而采样是 VAD 的前提），攒到 512 帧再发，避免每秒数百次消息淹没主线程。
      - 防自问自答：数字人播放语音期间冻结 VAD 判定（`vad.suppressed`），
        并在抑制期间继续估计噪声底 —— 否则解除抑制后阈值会失真（这是测试用例抓出来的坑）。
      - 界面：设置 → 形象 → 语音采集，含实时电平表（能量曲线 + 阈值线 + 说话区间底色），
        灵敏度与「说完判定时长」都可调。
      - 超时保护：`getUserMedia` / `resume` / `addModule` 全部限时，
        避免无设备环境下「点了麦克风没反应」这种无声卡死。
      - 自检：`web/dev/vad-lab.html`，**23 条断言全部通过**（含噪声自适应、长停顿切分、
        短噪声丢弃、超长强制收尾、抑制开关、WAV 头逐字节校验）。
- [ ] 真 barge-in 的最后一公里：自动模式下用户开口即掐断 TTS 播放
      （协议层 `interrupt` 已就绪、`interruptSpeakingFor` 已接好，待真人麦克风实测）
- [ ] 音频重采样与格式协商下沉后端（当前自动模式固定发 16bit 单声道 WAV）
- [ ] 「自动断句 + 浏览器本地识别」这一组合做不到：Web Speech 只能听实时麦克风流，
      吃不到我们要送出的 PCM。要既自动断句又不出本机，得装本机 whisper。
- 前置条件：安装 ffmpeg（本机 ASR 解码、TTS 后处理、口型特征提取都依赖它）
