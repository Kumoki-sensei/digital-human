## 零、怎么用这份文档

- 说「某个阶段完成了」时，**必须逐条勾掉它下面的完成判据**，勾不掉就是没完成。
- 判据里的「真机验证」项**不接受自动化环境的通过** —— 自动化环境验不了麦克风与音频。
- 每次发现文档与代码不符，**立刻补进 §五「宣称完成 vs 实况」**，不要让它悄悄过期。
- 阶段顺序可以调整（例如把 M4-a 提前），但**「验收串行」这条不能破**。

## 一、划分原则

1. **阶段 = 能力跃迁，不是工作量累积。**
   跨过一阶段，意味着「使用者能做的事」发生了质变（从打字到说话、从聊天到干活），
   而不是「代码变多了」。所以阶段数很少，每阶段有一句话能说清的价值。

2. **判据必须可验收。**
   每条完成判据都要能用**一个具体动作**验证真假，例如「连续说 10 句话不用碰鼠标」。
   禁止出现「优化了体验」「提升了稳定性」这类无法判定真假的描述。

3. **准备可并行，验收必须串行。**
   下一阶段的技术预研随时可以做（比如 M1 期间就先把 Cubism Framework 接通了），
   但**上一阶段未验收通过，下一阶段的成果不计入完成**。

4. **严格区分「写完」与「验证过」。**
   这是本项目最容易犯的错，也是本文存在的最大理由：
   未验证清单里绝大多数条目都是「代码写了但没在真机验过」。
   **本项目的默认状态假设是「未验证」，除非有证据。**

## 三、逐阶段定义

### M0 · 骨架（Walking Skeleton）— ✅ 已验收

**目标**：证明整条链路**存在且可替换** —— 不配密钥能跑，配上自己的密钥能真思考。
这一阶段不追求好用，追求的是「骨架立起来了」。

**进入条件**：无（起点）。

**交付物**
- FastAPI 服务 + WebSocket 双向流（文本 / 二进制音频 / 打断 / 流式事件）
- 四能力注册表 + Protocol 契约，OpenAI 兼容协议可插拔
- 用户自带密钥通道（连接参数 `p=cap.field:value`，即用即弃、不落盘、不进日志）
- 会话记忆：滚动窗口 + 原子落盘 JSON，重启可续
- 前端三件套分离（原生 ES Module，无构建）+ 换肤 + 无模型降级
- 工具注册表 + 声明式自定义模块（填 JSON 接任意 HTTP 接口）
- 视觉：截屏 / 摄像头取帧 → 多模态模型；涉及隐私必走确认中心
- 开发辅助：`tools/check_env.py` 环境自检、Core 与示例模型下载脚本、`scripts/dev.ps1`

**完成判据（可验收）**
- [x] 一条命令启动，`/` 出网页、`/docs` 出接口文档
- [x] **不配任何密钥**：打开网页能文字对话（离线回声大脑）
- [x] 网页填自己的 Key → 得到真实 LLM 流式逐字回答
- [x] 日志与错误信息中密钥只以 `sk-a…z9` 形式出现（`log_hygiene.py` 机械清洗）
- [x] 关掉网页再打开 / 重启后端，会话历史能续上
- [x] 换供应商只改一处（注册表一行 或 网页填 JSON），不动其它代码

**当前状态**：✅ 通过。**但有一项欠账**：README 把「确认中心（写操作两段式确认）」列为已完成，
实际闭环是断的（详见 §五 · 差异 #1）。该项归 M0，应作为 M1 的前置修复。

### M1 · 语音链路硬化（Voice I/O）— 🔄 进行中

**目标**：把输入输出从「打字 / 看字」升级为「开口说、听得见、随时打断」。

**进入条件**：M0 验收通过（已完成）。

**交付物（已完成部分）**
- **延迟仪表盘**：三段埋点 —— 听懂(ASR) / 首字(LLM) / 首帧(TTS)，外加每次工具耗时与
  每个分句的合成时长；点状态栏的 `xxxxms` 展开分解，每轮结束自动亮出。
  浏览器 TTS 拿不到音频流，首帧值标注为「墙钟估算」不假装精确。
  后端同时打一行 `本轮耗时：听懂 x｜首字 y｜首帧 z｜工具 n 次` 进日志。
- **VAD 自动断句**：说完自动发送，不用再点麦克风。
  - `web/scripts/vad.js`：算法与浏览器 API 完全解耦（只吃 Float32 PCM + 时间戳），
    所以能离线单测；自适应噪声底 + 三段状态机（静音/说话/完成）+
    最短语音过滤（咳嗽、键盘声）+ 最长时长兜底。
  - `web/scripts/mic-worklet.js`：AudioWorklet 取原始 PCM（MediaRecorder 拿不到采样，
    而采样是 VAD 的前提），攒到 512 帧再发，避免每秒数百次消息淹没主线程。
  - 防自问自答：数字人播放语音期间冻结 VAD 判定（`vad.suppressed`），
    并在抑制期间继续估计噪声底 —— 否则解除抑制后阈值会失真（这是测试用例抓出来的坑）。
  - 界面：设置 → 形象 → 语音采集，含实时电平表（能量曲线 + 阈值线 + 说话区间底色），
    灵敏度与「说完判定时长」都可调。
  - 超时保护：`getUserMedia` / `resume` / `addModule` 全部限时，
    避免无设备环境下「点了麦克风没反应」这种无声卡死。
  - 自检：`web/dev/vad-lab.html`，**23 条断言全部通过**（含噪声自适应、长停顿切分、
    短噪声丢弃、超长强制收尾、抑制开关、WAV 头逐字节校验）。
- 浏览器原生 ASR/TTS 兜底；本机 faster-whisper / piper 实现

**完成判据（可验收）**
- [x] VAD 算法可**离线自检**，不开麦克风也能跑（`web/dev/vad-lab.html`，23 条断言）
- [x] 说完停顿后自动发送（算法层已成立）
- [x] 每轮结束能点开延迟分解，看见三个数
- [ ] **真机验证**：真人 + 真麦克风，连续说 10 句话不用碰鼠标，每句都自动送出
- [ ] **真 barge-in**：她正在说话时，用户开口即掐断播放（不是等她说完了才响应）
      （协议层 `interrupt` 已就绪、`interruptSpeakingFor` 已接好，就差真人麦克风实测）
- [ ] 本机 ASR / TTS 端到端跑通（需先装 ffmpeg + `local-asr`/`local-tts` extras）
- [ ] 音频重采样与格式协商下沉后端（当前自动模式固定发 16bit 单声道 WAV）

**当前状态**：🔄 算法与仪表盘**已完成**；4 项真实验证**全部未做**。

> 为什么卡住：自动化环境里 `AudioContext` 必然 suspended、也没有麦克风，
> 这 4 项**只能在有麦克风、有人点过页面的真机上手验**。不是代码问题，是环境问题。
>
> **M1 的完成不看代码量**，只看这一件事：真人对着麦克风自由说话，全程不用碰鼠标，
> 且任意一句能被她「停下来听」。

**前置条件**：安装 ffmpeg（本机 ASR 解码、TTS 后处理、口型特征提取都依赖它）。

**已知边界（不是待办，是结论）**：「自动断句 + 浏览器本地识别」这个组合做不到 ——
Web Speech 只能听实时麦克风流，吃不到我们要送出的 PCM 段。
要既自动断句又不出本机，只能装本机 whisper。

### M2 · 形象与表现力（Presence）— ⏸ 未开始

**前置**：待拍板 #3（一期是否必须有真 Live2D 模型 / 谁提供已授权 moc3）。

**目标**：屏幕上是「一个角色」，而不是一块空状态引导图。

**进入条件**：M1 验收通过（语音链路稳定，否则口型没有意义）。

**交付物**
- 真 Live2D 模型实机渲染（官方 Cubism Web Framework 链路**已就位**）
- 情绪标签 → Expression / Motion 映射
- 情绪模块升级：从「关键词启发式」换成真实分类（当前 `guess_emotion` 是词表匹配，
  驱动表情 + 音色 + 语速）
- 待机行为：呼吸、眨眼节奏、视线跟随手感

**完成判据（可验收）**
- [ ] 加载一个**已授权** moc3，实机渲染出连贯完整的角色（无白屏 / 无碎片 / 五官不被头发盖住）
- [ ] 说一句话，能肉眼看出表情随内容变化（happy / sad / surprised 有区别）
- [ ] 播放语音时口型与音频同步（**真人手势下**，非自动化环境）
- [ ] 无模型时降级为「空状态引导」，不白屏、不画假形象

**当前状态**：⏸ 卡在两处 —— ① **实机画面输出未验证**（代码链路完整，但「能渲染」
没有被真人确认过）；② 缺一个**已授权**的 moc3 模型。

### M4 · 工程化与可交付（Hardening）— ⏸ 未开始

**前置**：无。**这是唯一建议立刻开始、不要排到最后的一阶段**（理由见下）。

**目标**：让下一个人（或三个月后的你）敢改这份代码。

**进入条件**：无（可随时开始，且越早越好）。

**交付物**
- pytest：覆盖后端关键路径（brain 轮次 / session / log_hygiene / custom_modules 校验 / 分句器）
- 前端 lint（当前 ruff 已配但未接 CI）
- CI：lint + test，提交必过
- 拆上帝模块：`web/scripts/ui.js`（1953 行）、`backend/api/routes.py`（747 行）
- 安全三连：`themes.js` 皮肤动态 import 白名单、模型上传体积上限、鉴权 + CORS 收紧

**完成判据（可验收）**
- [ ] `pytest` 有真实用例且全绿（当前**全仓库 0 个测试文件**）
- [ ] CI 在每次 push 上跑 lint + test，红灯阻断合并（当前**无任何 CI 配置**）
- [ ] `ui.js` 拆到每个文件 ≤ 400 行；`routes.py` 按资源拆分成多个 router
- [ ] 皮肤动态 import 走白名单（拒绝任意路径）
- [ ] 管理类接口需要鉴权；CORS 不再是 `*`

**当前状态**：⏸ **0 测试、0 CI**。三处安全项里，**模型上传体积上限已完成**
（单文件 32MB / 单次 200MB，含路径穿越与后缀白名单防护），另两处未做。

> **为什么不建议排到最后**：M1 和 M2 的核心难点全是「真机验证」——

> 建议把 M4 拆成两条线：
> - **M4-a（立刻做）**：CI + 后端关键路径测试。这是后面所有阶段的保险。

## 五、宣称完成 vs 实况（诚实清单）

文档说「已完成」但代码与实际不符的地方。这类差异最危险 —— 它让排期建立在错误前提上。

## 六、踩坑记录（排障花掉的时间都在这，别再踩）

### 6.1 运行时坑（前后端行为）

| 坑 | 表现 | 根因与结论 |
|---|---|---|
| **语音播报默认开着** | 用户一发消息网页就自己开口说话，把人吓一跳 | 会出声的功能默认必须关。`voice.autoplay` 默认 false，且前后端两个开关（`autoplay` / `tts_enabled`）要分清 |
| 开关发了后端不认识的字段名 | 勾了「自动播放」却没声音：前端发 `autoplay`，后端只认 `tts_enabled` | 前后端协议字段以 `api/schema.py` 为准，别自造名字 |
| Starlette `MutableHeaders` 没有 `.pop()` | 所有静态资源 500 → 前端整体不加载 | 只能用 `del headers['etag']`；写 `pop` 直接崩 |
| 浏览器缓存前端 JS/CSS | 改完代码刷新看到的还是旧逻辑，排查方向全跑偏 | `backend/main.py` 的 `NoCacheStaticFiles` 强制 no-cache |
| 同一事件被两处渲染 | 每句回复在界面上出现两遍；监听器数量与模块实例数都正常，极难定位 | **一个事件只允许有一个渲染者**（当时 `browserSpeak` 与 `ws:segment` 各渲染一次） |
| `MediaRecorder` 产出的 webm | 部分环境 `decodeAudioData` 解码失败 | `audio.js` 保留 `<audio>` 兜底路径，口型退化用估算能量 |
| AudioContext suspended | 自动化环境里永远无声、能量恒 0 | 浏览器要求用户手势，真人点一次即可；**不是代码问题** |
| WebSocket 重连有次数上限 | 后端重启后网页永久失联 | 改无限重试 + 退避封顶 30s，且 `visibilitychange` / `online` 立即重试 |
| 「清空记忆」只发 reset 不换 session | 刷新后旧历史又回来了 | 必须换新 session id 并重连 |
| 前端密钥明文存 localStorage | 同机其他程序、浏览器扩展理论上可读 | **已知并接受的代价**（自用）。多用户必须改后端加密存储 —— 见拍板 #5 |
| 工具往返没有上限 | 模型绕不出来时会无限自我调用，账单和延迟一起爆炸 | 一轮最多 3 次往返（`MAX_TOOL_ROUNDS`） |

### 6.2 Live2D 渲染坑（详见 `docs/live2d-render-fixes.md`）

自写渲染器时期踩的坑 —— 这些对理解 Cubism Core 的数据约定仍然有用
（坐标空间、位标志、绘制顺序，三条都容易读错且**不报错**）。

| # | 坑 | 表现 | 结论 |
|---|---|---|---|
| 1 | 顶点单位与「世界」不一致 | `drawn=69`、`glError=0`，屏幕全空 | 顶点是**模型单位**不是像素；要统一到 `CanvasWidth/PPU` |
| 2 | `constantFlags` 位定义凭直觉猜 | 整只模型 alpha 全灭 | 真实定义：`0x01` 加法混合、`0x02` 乘法混合、`0x04` 双面、**`0x08` 才是反转遮罩** |
| 3 | 乘法混合因子用错 | 阴影区域发黑或消失 | 着色器输出的是**预乘**色 → `blendFunc(ZERO, ONE_MINUS_SRC_ALPHA)` |
| 4 | 绘制顺序没按 `renderOrders` 重排 | 模型像散开的碎片、五官被头发/衣服盖掉 | `drawables` 数组**不是**按绘制顺序排的；`renderOrders` 挂在 **CoreModel** 上 |
| 5 | CSS 与 JS 状态撕裂 | 模型加载好了却永远停在「请把模型文件放进来」 | `index.html` 静态写 `data-mode="empty"`，而 `avatar.js` 只切 class → canvas `display:none` → `clientWidth=0` → 一帧不画 → 被判「没画出」→ **自锁死循环** |
| 6 | 视口按画布缩放 | 形象在竖屏窗口里缩成一小块 | 按**顶点包围盒**做 contain，不是按画布 |

**换到官方 Cubism Web Framework 时又踩的**：

| # | 坑 | 结论 |
|---|---|---|
| 7 | 类必须继承 `CubismUserModel` | 基类要等 Framework 异步装配完才拿到 → 只能用**工厂函数动态造类** |
| 8 | `CubismModelSettingJson` 要的是**原始字节** | 传解析好的对象进去报 `Unexpected end of JSON input` |
| 9 | 渲染器要显式 `startUp(gl)` | 否则内部 gl 为 null，第一帧就炸在 `bindFramebuffer` |
| 10 | 遮罩管理器拿不到 gl | 官方 `startUp` 只对「已存在」的管理器 setGL，而遮罩管理器是 `initialize()` 里建的 → 需 `_ensureClippingGl()` 幂等补齐 |
| 11 | API 名字全靠实测 | `getModelFileName`（不是 getMocFileName）· 表情用 `expressionManager.startMotion`（没有 addExpression）· 动作用 `startMotionPriority`（没有 addMotion）· 呼吸用 `breath.setParameters`（类名没有 Cubism 前缀） |
| 12 | 不要把遮罩缓冲调到 1024 | 82 个 drawable 会各开一块 1024² 离屏 FBO，成本高得没必要（用官方默认 256） |
| 13 | 不要每帧读像素 | 同步 `readPixels` 会打断 GPU 流水线；自检只做开头 8 帧 |
| 14 | 页面隐藏时定时器被节流到 ~1Hz | 调试时「帧数不涨」很可能不是卡死，先看 `document.visibilityState` |

### 6.3 工程环境坑（git / 换行 / 代理）

| 坑 | 表现 | 结论 |
|---|---|---|
| **全局 git 代理指向失效端口** | 所有远端操作报 `Failed to connect ... over proxy 127.0.0.1` | 原值 `socks5://127.0.0.1:28317` 无监听 → 已 `git config --global --unset http.proxy https.proxy`。要用代理时重新设：`git config --global http.proxy <地址>` |
| 后台跑 `git push` 静默挂死 | 进程不报错也不退出 | GCM 需要人完成浏览器 OAuth，`GIT_TERMINAL_PROMPT=0` 对它无效。出路：人手动跑一次，或配 SSH key（**现已配 ed25519 空口令，具备非交互推送能力**） |
| Windows 换行警告刷屏 | 每次 `git add` 一堆 `LF will be replaced by CRLF` | `.gitattributes` 统一：`* text=auto eol=lf`，`*.bat/.cmd/.ps1` 固定 CRLF |
| 远端与本地是无关历史 | 直接推送会被拒 | 用 `git reset --soft origin/main` 而非强推，得到干净线性历史 |
