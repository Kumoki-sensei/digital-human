# 「Live2D 形象像抽搐一样」的排查记录

## 结论（最终）

**抽搐的真凶是官方的 `CubismBreath`（呼吸更新器）：它算出的参数在帧间乱跳。**

实测证据：同一个时间值 `t` 连续调用四次，得到一个**互不相同、而且和
`sin(t / cycle)` 对不上的**结果：

| 第几次 | `ParamAngleX` 实际值 | 正确值 |
|---|---|---|
| 1 | −6.3762 | |
| 2 | −6.3664 | **+3.1485** |
| 3 | −6.3564 | |
| 4 | −6.3464 | |

同一时刻、同一模型，直接 `setParameterValueByIndex(idx, sin(t/6.5345)*15*0.5)` 四次
全部是 `3.1485`（稳定），走官方 breathing updater 就漂。它写进模型的值每帧都能差
几度到十几度 —— 头部/身体在帧间来回抽，肉眼就是「抽搐」。

**修法**：呼吸不值当去查官方内部的账，直接自己算 —— 呼吸本来就是一条正弦。
现在 `_applyBreath(t)` 用 `offset + peak * sin(t / cycle)` 逐分量计算，
只用 `setParameterValueByIndex` 落到「当前值」，不依赖任何内部累计状态。

### 修完的实测对比

| 指标 | 修之前 | 修之后 |
|---|---|---|
| `ParamAngleX` 每帧变化 | 平均 **9.0 度**（最大 14.5） | 平均 **0.0034 度**（最大 0.0068） |
| 画面每帧变化的像素数（200×260 采样区） | **12,000 ~ 20,000** | **0 ~ 86（平均 8）** |

## 我是怎么一步步缩小到它的（过程有用，别只看结论）

1. **先证伪「参数跳变」**：一次调用内连跑 120 帧统计所有参数极值 → 35 个参数没有任何
   一个波动超过 0.6。**这个结论后来被推翻了** —— 因为我在同一次调用里连续调用 `update()`
   时，呼吸的时间基几乎没前进，`sin` 一直停在同一个相位（见下面的陷阱二）。
2. **再怀疑帧率**：`__dhAvatar.fpsStats` 量出 `p50Ms ≈ 994`，即渲染循环被浏览器节流到
   1Hz。这在**页面不可见**时确实会发生，也值得修（已修：降级后重试 rAF + 可见时切回），
   但它不是抽搐的主因 —— 用户说修完还在抽。
3. **转向画面本身**：同帧读两次像素完全一致（证明测量可靠），于是改测**相邻帧的像素差**
   → 每帧 23~40% 的像素在变、幅度极大。参数平滑而画面剧烈变化，矛盾出现。
4. **逐个模块关掉做对照**（同一次调用内跑，避免跨调用误差）：

   | 条件 | `ParamAngleX` 每帧变化 |
   |---|---|
   | 正常 | 平均 8.96 / 最大 14.5 |
   | 关掉呼吸 | **0** |
   | 关掉眨眼 | 12.06（仍然抽） |
   | 屏蔽 Core 的 `update` | 8.64（仍然抽） |

   只剩呼吸。定位完成。

## 两个把我误导过的陷阱（很重要）

### 陷阱一：跨调用采样会造成「假跳变」

呼吸的相位是**时间**的函数。两次观测之间隔了几秒，相位就前进了几秒 —— 你会看到角度
在 ±7 之间"乱跳"，误判成抽搐。**判定参数是否平滑，必须在同一次同步调用里连续采样。**

### 陷阱二：同一次调用里连续 `update()` 会掩盖真实的相位推进

如果时间基用的是 `performance.now()`，那在一次同步循环里连续调 120 次 `update()`，
真实时间几乎没走，`sin` 就停在同一个相位上 —— 于是"参数很平滑"这个结论是**假的**。
这次的教训是：验证平滑性时要么用固定步长时间基，要么直接检查「每帧的实际差
是不是符合周期」。我最后是靠 `sin` 期望值与实际值对比才抓住官方的漂移。

## 附带修掉的实现问题（都在 `web/scripts/avatar.js`）

1. **降级后不再重试 rAF**：只要 rAF 晚回一次就永久留在被节流到 1Hz 的 setTimeout 路径上。
   现在降级期间每 8 帧重试一次 rAF。
2. **页面重新可见时没有立刻切回 rAF**：现在监听 `visibilitychange`。
3. **帧率统计把隐藏期间的空档也算进去**，导致可见时也谎报 `fps=1`。现在超 1 秒的间隔不计入。

## 浏览器限制（与本次抽搐无关，但值得知道）

后台标签页的 `setTimeout` 下限是 ~1 秒，这是浏览器强制的。窗口被遮挡/最小化时画面会变慢，
属正常现象；Worker 也不解决（画面最终要在主线程合成）。

## 怎么自查

```js
// 帧率（窗口可见时应当接近 60）
window.__dhAvatar.fpsStats

// 呼吸是否平滑：maxFrameDelta 应当在 0.01 度量级
const m = document.querySelector('#live2d-canvas').__dhModel;
const s = [];
for (let i = 0; i < 40; i++) { m.update(1/60); s.push(m.getParameter('ParamAngleX')); }
const d = s.slice(1).map((v, i) => Math.abs(v - s[i]));
console.log('每帧最大变化', Math.max(...d));
```
